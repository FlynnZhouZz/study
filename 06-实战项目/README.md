## 项目记录 vs 立项模板

[02-项目记录](./02-项目记录/README.md) 里放的是**已经发生过的**实施记录——读它看的是「当时为什么这么选」。
下面的模板是给**还没开始**的项目用的：先写立项，做完补复盘，比事后回忆更有用。

## 项目立项模板

每个实战项目在本目录下建一个子目录，包含三份文档：

```text
06-实战项目/
└── 项目名/
    ├── README.md      项目定位、技术选型、功能清单
    ├── 笔记.md        踩坑记录（按时间倒序，最新的在最上面）
    └── 复盘.md        做完了回头看：哪里设计错了、下次怎么做
```

**README.md 至少回答四个问题**

1. 解决什么问题？谁会用？
2. 技术栈为什么这么选？（对比至少一个备选方案）
3. 核心难点是什么？打算怎么解？
4. 验收标准是什么？（列出可检查的功能点）

## 建议的项目梯度

| 阶段 | 项目类型 | 用到的层 |
|------|----------|----------|
| 入门 | 纯静态站 + 响应式布局 | 02 前端核心 |
| 进阶 | 后台管理系统（登录 + 权限 + 增删改查） | 02 + 03 + 05 |
| 全栈 | 内容发布平台（前后端 + 数据库 + 部署） | 02 + 04 + 05 |
| 跨端 | RN 应用上架（含原生模块） | 03 + 04 |

> 每个项目完成后，把过程中暴露的知识漏洞记到 [进度看板](../00-路线/02-进度看板.md) 的盲点清单。
